# 0.2.0 更新说明与真机复测

用户反馈 0.1.0 在实体手机可连接和使用，但实时画面延迟明显。0.2.0 针对可确认的应用侧等待和 USB 争用进行优化；实际从相机画面变化到手机显示的端到端延迟仍需同一台手机/相机对比测量。

## 取景优化

旧版每帧串行执行 USB → JPEG 解码 → 固定等待 200 ms，即使相机和手机足够快，也只能达到低于 5 FPS。新版移除固定等待，按照目标帧率减去 USB 请求已经耗费的时间。

取帧和解码分别运行，以单槽 Channel.CONFLATED 传递数据；解码跟不上时丢弃旧的待解码帧，不累积预览队列。不并发发出 PTP 命令，仍维持完整事务互斥以保护协议。

USB 读取改为复用 64 KiB 缓冲区，避免每 16 KiB 重新分配和复制临时缓冲。Android 10 的最低版本允许此传输大小。解码使用可选的像素尺寸和 RGB_565，缓存 JPEG 起始偏移并逐帧校验。画面由独立 StateFlow 发布，设置和相册不订阅逐帧 Bitmap。

默认“监看优先”开启：实时取景时不扫描整张存储卡，也不启动 JPG/NEF 整文件下载。停止监看后继续发现并接收新照片。App 拍摄依旧先停止取景，再拍照和传图。关闭优先模式可边看边传，但完整 GetObject 事务无法在中间插入取景指令，传图期间会出现停顿。

设置里的预览尺寸仅减少手机解码负担，不改变相机实际传出的 USB JPEG 尺寸。30 FPS 是请求目标上限，设备和 USB 速度决定实际帧率；不保证达到 30 FPS。

“本机 xx ms”记录 PTP 取帧请求开始到 JPEG 解码结束的耗时，包含可能的锁等待和解码排队，不是实测相机曝光到屏幕亮起的端到端延迟。诊断导出可分别查看取帧和解码耗时。直方图每约 300 ms 对预览采样，表示 JPEG 亮度分布，并非 RAW 传感器直方图。

## 独立页面

- 监看：沉浸式、横屏选项、可隐藏参数侧栏。菜单可选择完整画幅或填满区域（后者会裁切）。网格包括关闭、九宫格、四等分、黄金分割、中心十字；可切换亮度直方图。
- 参数：单屏显示 ISO、快门、光圈和调节按钮，含 USB 连接和拍摄。横屏与竖屏采用不同布局。
- 相册：仅显示本应用导入且属于本应用的 JPG/JPEG，每页 6 张；点击可大图查看、双指缩放、上一张/下一张和分享。不读取用户所有相册，也不显示 NEF。
- 设置：监看、传输、常规和诊断分类；所有选项持久保存。可配置帧率、解码尺寸、网格、直方图、监看优先、自动传图、NEF、检查间隔、横屏、常亮、沉浸式、后台暂停、连接后自动取景等。

## JPG / NEF

默认仅接收 JPG/JPEG。关闭 NEF 时，在读取 ObjectInfo 后就跳过该对象，不进行 GetObject。开启 NEF 后，新增 JPG 优先传输，NEF 保存到 Download/Nikonect/NEF；JPG 保存到 Pictures/Nikonect。相册始终只显示 JPG。选项在下一次传图前检查，已经进行中的 PTP 文件事务会完成；曾经跳过的旧 NEF 不自动补传。

## 建议第一轮真机设置

保持“监看优先”开启、“传输 NEF”关闭，目标 30 FPS，解码尺寸 960 或 1280。比较走动/指针等持续变化场景，记录屏幕显示的 FPS 与本机耗时；分别测试关闭直方图和 640 解码尺寸，看瓶颈是否在手机 CPU。没有做真实硬件对比前，不声明具体减少了多少毫秒。

验证：监看期间不被 JPG/NEF 下载打断；停止后补传；JPG+NEF 拍摄时 NEF 关闭只下载 JPG；开启 NEF 后两者都正确保存而相册仅显示 JPG；横竖屏和前后台切换不丢设置，应用升级覆盖安装保留已有照片。
